# 矛盾的默认值规则

## 问题描述

在Business Rules中对同一情况给出了**矛盾的指令**：一条规则要求"必须使用默认值"（强制性），另一条规则却说"可以使用默认值，也可以询问用户"（可选性）。这种矛盾导致Agent可以选择遵循其中任何一条，最终选择了与业务意图相悖的行为。

## 实际案例

**场景**：shortdrama（短剧创作助手）
**失败模式**：FP7 - 过度询问用户（Prompt遵循不足）
**影响样本数**：10/33 (30%)
**评测时间**：2026-01-16（ernie-5.0-thinking-preview）

### 具体表现

**矛盾的两条规则**：

- **规则2：集数确定逻辑**
  ```markdown
  - 必须完成用户指定的所有集数
  - 如果用户未指定集数，则使用默认值：3集
  ```
  → 语义：强制性（"则使用"）

- **规则5：用户交互要求 - 情况2**
  ```markdown
  当以下关键信息缺失时，必须主动询问用户：
  1. 题材信息缺失 - 用户未明确说明要做哪个题材的短剧
  2. 集数信息缺失 - 用户未指定集数（可使用默认值3集，也可询问确认）
  ```
  → 语义：可选性（"可使用...也可询问"）

**Agent的实际行为**：

```
[轮1] User: 我想做一个女性复仇爽剧。
[轮2-4] Agent: [成功读取skill手册]
[轮5] Agent: 我已经查阅了复仇爽剧的创作手册...
             根据业务规则，我需要先确认几个关键信息：
             1. **集数要求**：您希望这部复仇爽剧做几集？如果不指定，默认是3集
             2. **平台偏好**：小程序平台...还是TV平台？

             请告诉我您的偏好，我将立即开始创作选题简报。
[对话终止] 用户模拟器未响应
```

**为什么用户模拟器不响应**：
- 用户已经提供了完整需求（题材明确）
- Agent应该直接使用默认值3集开始创作
- 询问集数是非必要的，用户模拟器被设计为不回复非必要问题

## 根本原因

### 为什么会出现矛盾

1. **规则编写时的局部视角**：
   - 规则2单独看是清晰的："用户未指定 → 使用默认值"
   - 规则5单独看也是合理的："信息缺失 → 询问用户"
   - 但两条规则组合后产生了逻辑冲突

2. **"可选性"表述的危险**：
   - "可使用A，也可使用B"给了Agent选择权
   - Agent在面对两个选项时，倾向于选择"询问用户"（更保险）
   - 但这违反了规则2的强制性意图

3. **规则间缺乏优先级关系**：
   - 没有明确规定：当规则2和规则5冲突时，应该遵循哪一条
   - Agent只能自行判断，导致不同样本中行为不一致

### 为什么这个问题严重

1. **影响范围大**：30%的样本因此失败
2. **能力误判**：Agent实际具备完成任务的能力（成功读取了手册），但被Prompt矛盾困住
3. **check项失去意义**：用户模拟器不响应是正确的行为，但导致Agent无法继续执行
4. **逻辑自洽性破坏**：Check失败时无法明确引用单一规则，因为存在矛盾规则

## 解决方案

### 修改前（错误的设计）

```markdown
### 规则2：集数确定逻辑
- 如果用户未指定集数，则使用默认值：3集

### 规则5：用户交互要求
#### 情况2：关键信息缺失时的询问
当以下关键信息缺失时，必须主动询问用户：
1. 题材信息缺失
2. 集数信息缺失 - 用户未指定集数（可使用默认值3集，也可询问确认）
```

**问题**：
- 规则2是强制性（"则使用"），规则5是可选性（"也可询问"）
- 两条规则对同一情况给出不同指导
- Agent可以选择遵循其中任何一条

### 修改后（正确的设计）

```markdown
### 规则2：集数确定逻辑
- 必须完成用户指定的所有集数
- 如果用户未指定集数，则使用默认值：3集
- 大纲文件数和剧本文件数必须与确定的集数一致

### 规则5：用户交互要求

**总则**：
- 优先通过HITL工具交互，其次在对话中询问
- **只询问规则5明确列出的缺失信息，其他情况使用默认值或自行决策**

#### 情况1：关键阶段完成后的确认
必须在以下节点主动请求用户确认：
1. 选题简报完成后
2. 角色卡全部完成后
3. 分集大纲全部完成后

#### 情况2：关键信息缺失时的询问
**仅当题材信息缺失时**必须询问用户（如：用户只说"我想做短剧"）

**其他信息**：
- 集数：使用规则2的默认值（3集）
- 其他细节：根据skill手册自行决策
```

**改进点**：
1. ✅ **增加总则**：明确规定"只询问规则5明确列出的缺失信息"
2. ✅ **删除矛盾表述**：移除"也可询问确认"的可选性描述
3. ✅ **显式引用规则2**：在规则5中明确说明"集数：使用规则2的默认值"
4. ✅ **明确细节决策**：规定其他细节由Agent根据skill手册自行决策
5. ✅ **单向逻辑链**：规则间形成清晰的引用关系，无循环依赖

### 修改效果

**修改前**：10个样本（30%）因Agent过度询问导致对话终止
**预期修改后**：Agent应直接使用默认值开始创作，这10个样本成功率提升

## 通用原则

### ✅ 正确做法

1. **默认值语义明确**
   - ❌ "可使用默认值A，也可询问"
   - ✅ "使用默认值A"（强制性，无退路）

2. **增加总则性描述**
   - 在复杂规则开头增加总则，明确规定何时可询问、何时应使用默认值
   - 例如："只询问规则5明确列出的缺失信息"

3. **规则间显式引用**
   - ❌ 重复描述："集数未指定时使用3集"（在多个规则中重复）
   - ✅ 显式引用："集数：使用规则2的默认值"（建立规则间链接）

4. **避免模棱两可的表述**
   - ❌ "可以A，也可以B"
   - ❌ "建议A，但可以B"
   - ❌ "通常A，特殊情况B"
   - ✅ "必须A"
   - ✅ "仅当X条件时B，其他情况A"

5. **规则间一致性检查**
   - 编写完所有规则后，检查是否存在矛盾
   - 特别关注：默认值逻辑、条件判断、优先级关系

### ❌ 错误做法

1. **隐性矛盾**
   - 一条规则说"必须X"，另一条规则说"可以不X"
   - 即使不是直接冲突，也会导致Agent选择困难

2. **局部视角编写规则**
   - 每条规则单独看都合理，但组合后产生冲突
   - 缺乏全局一致性检查

3. **给Agent过多选择权**
   - 对于关键业务逻辑，不应该让Agent"自由选择"
   - 明确规定唯一正确的行为路径

4. **规则间缺乏优先级**
   - 当多条规则可能适用时，没有明确哪条优先
   - 导致Agent行为不稳定

## 触类旁通：其他可能出现矛盾的地方

1. **任务范围判断**
   - 规则A："完成所有阶段"
   - 规则B："用户明确指定时只完成指定范围"
   - → 当用户说"请帮我做短剧"时，是否应该完成所有阶段？

2. **信息收集策略**
   - 规则A："尽量减少用户打扰"
   - 规则B："关键信息缺失时必须询问"
   - → 什么是"关键信息"？需要明确列出

3. **错误处理策略**
   - 规则A："遇到错误主动尝试修复"
   - 规则B："重要操作失败时告知用户"
   - → 什么是"重要操作"？如何判断"可修复"？

## 经验总结

**这个陷阱的本质**：当业务逻辑中存在"默认值"概念时，必须确保：

1. 默认值的触发条件是唯一的、明确的
2. 不能同时提供"使用默认值"和"询问用户"两个选项
3. 如果确实需要询问，则不应该设计默认值

**设计决策**：
- 如果业务逻辑允许"没有明确指定就使用默认值"，则不应该在任何规则中提供"也可询问"的选项
- 如果业务逻辑要求"必须询问用户确认"，则不应该设计默认值

**与Check设计的关系**：
- 矛盾的规则导致Check失败时无法"师出有名"
- 修复后，Check失败可以明确引用单一规则："未遵循规则2的默认值逻辑"
